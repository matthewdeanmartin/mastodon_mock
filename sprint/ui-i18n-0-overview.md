# i18n — Epic overview: speaking 60 languages without a translation department

Status: PLANNED

> **Not to be confused with [[i18n-lists-0-overview]]'s Track A.** That epic translates *post
> content* for language learners (the per-post translate button, spend guards, bulk trigger).
> This one translates *the interface itself*. They share the word "translation" and the
> `pages/settings/i18n/` page, and nothing else. Files here are prefixed `ui-i18n-` for that
> reason.

Retrofitting internationalization onto an app that was English-only for its whole life, in a
codebase that gains features every week and is maintained by one person. Both of those facts
constrain the design more than the usual i18n advice accounts for.

## The premise nobody else's i18n guide is written for

Standard i18n advice assumes a translation *organization*: a string freeze, a vendor, a review
cycle, a release train that waits for locales. None of that exists here. What exists is:

- **One maintainer**, who is not going to learn 50-60 languages.
- **No budget** for human translators at ~3000 strings × 60 locales.
- **No volunteer community** large enough to cover Icelandic and Finnish on any useful timeline.
- **A frontier LLM**, which can do this work well *if it is told what the words mean*, and
  catastrophically if it is handed a bare JSON file.

So the epic optimizes for something unusual: **the marginal cost of the 61st language must be
near zero, and the marginal cost of a new feature must not scale with the number of locales.**
Every design decision below falls out of those two sentences.

## Why translation quality is a tooling problem, not a model problem

Hand a model `{"status.boost.action": "Boost"}` and ask for Chinese, and you may well get the
verb meaning "to promote / increase" — or, worse, something in the register of a municipal
economic-development slogan. The model is not being stupid; **it has been given a word with no
referent.** `Boost` here is a specific fediverse noun-verb meaning "re-share someone else's post,
unmodified" — closer to "retweet" than to any dictionary sense of boost.

The same trap is everywhere in this app's vocabulary:

| String | Naive translation | What it actually means |
|---|---|---|
| Boost | increase, promote, amplify | re-share a post unmodified |
| Post | fence post, mail, position | a status message |
| Toot | a horn sound | a post (Mastodon's older word) |
| Handle | grip, cope with | `@user@server.social` |
| Instance | example, occurrence | a server in the fediverse |
| Feed | to give food to | a stream of posts |
| Thread | sewing thread | a chain of replies |
| Follow | to come after | to subscribe to an account |
| Mute | silent | hide without unfollowing |
| Fail whale | a whale that failed | the error-page mascot |

**The fix is context, delivered as data.** Every key gets a sidecar entry saying what it means,
where it appears, how much room it has, and which glossary terms it uses. That context is written
**once per key**, never per locale — so it is paid for once and then amortized across all 60
languages, forever. This is the single highest-leverage artifact in the epic.

## Architecture in one page

**Transloco 8.4** (runtime dictionaries, not compile-time locale bundles). Chosen because the app
deploys as a **static SPA on GitHub Pages** with root + `/canary/` + subpath deployments guarded
by `check-subpath-deployments.mjs`. Angular's official `@angular/localize` bakes one bundle per
locale, which would multiply that build matrix by 60 and force every subpath guard, 404 shim, and
OAuth metadata stamp to become locale-aware. Runtime dictionaries keep **one** build and make a
locale a JSON file rather than a deployment.

```
ui/public/i18n/
  en.json              GENERATED from `// i18n <key>: <English>` comments. Never hand-edited.
  de.json fr.json ja.json fi.json is.json ru.json sv.json es.json
ui/i18n-context/       NOT under public/ — angular.json ships public/** verbatim
  en.context.json      HAND-WRITTEN. The translator's brief. The asset that matters.
  stamps.json          locale -> key -> hash of the English it was translated from
ui/src/app/i18n/
  locale.ts            UI locale signal + browser negotiation + persistence
  i18n.config.ts       provideTransloco wiring
  i18n.testing.ts      synchronous English loader for the shared-realm test suite
ui/src/app/locale-picker/   the footer widget
ui/scripts/
  extract-i18n.mjs     templates -> en.json  (+ reports context gaps)
  check-i18n.mjs       the build gate
  i18n-todo.mjs        emits a per-locale work file for the translating agent
.claude/skills/translate-ui/SKILL.md    how the agent must translate
```

### Keys are the source of truth, `en.json` is generated

Templates carry `{{ 'status.boost.action' | transloco }}`. `en.json` is generated by the extractor
and must never be hand-edited. Translated files are **plain hand-owned JSON that no tool ever
rewrites** — so there is no churn, no reformatting, and no re-translation bill when an unrelated
feature lands.

### Non-English coverage is reported, never enforced

This is the load-bearing decision for "don't break the app when a feature ships." `check-i18n`
fails on a *missing English key* or *hardcoded template text*; it only **reports** that Finnish is
at 71%. A new feature therefore ships in English immediately, and untranslated keys fall back
per-key to English. A Finnish user sees a mostly-Finnish UI with one English button — never a
crash, never a blocked merge, never a feature held hostage to 60 translation rounds.

## Language selection: browser first, user always wins

Three-tier precedence, highest first:

1. **Explicit user choice** — set via the footer picker or Settings, persisted in `ClientPrefs`.
   Once set, it is never overridden by anything.
2. **Browser negotiation** — `navigator.languages` matched against shipped locales, best match
   wins (`de-AT` → `de`). A brand-new German-speaking visitor gets German on first paint, without
   being asked.
3. **`en`** as the floor.

The forcing case matters as much as the automatic one: the maintainer's browser reports English,
so **there must be a visible control to force any locale** regardless of browser signals, or the
translations cannot be reviewed at all. That control is the footer picker, and it is why the
widget lands in Sprint 1 rather than being deferred to polish.

## Scope

**In:** everything a user can read in `mastodon_mock/ui` — templates, `aria-label` / `title` /
`sr-only`, toasts, errors, empty states, validation messages, page titles.

**Out, deliberately:**

- **The mock server** (`mastodon_mock/*.py`). It emulates a Mastodon API; its payloads are
  protocol, not interface.
- **Anything a user cannot see** — log lines, dev diagnostics, `console` output, test fixtures.
- **Blog posts and docs** (`docs/`, `README`, "why I wrote this"). Out of scope by instruction;
  they need an editing pass before they would be worth translating.
- **Text that came from somewhere else.** `bundled-starter-kits.generated.ts`,
  `api-docs.generated.ts`, RSS and post content, server error strings, remote instance metadata.
  **We do not translate text we did not write.** It is generated from or fetched from an upstream
  source; translating it would fork it from its origin and desynchronize on the next regeneration.

## What is deliberately deferred

**Terminology is English-only. By decree** (2026-08-30), not as a deferral — this is a
permanent scope decision, not a sprint that might happen later. `terminology.ts` swaps
post/tweet/florp/skeet/toot at runtime across 16 word-forms, guarded by `check-terminology.mjs`.
In English `Boosted by {name}` composes fine. In German, Finnish, Icelandic and Russian the noun
inflects by case, and `florp` has no plural any translator can authorize. Non-English locales get
the canonical noun from their dictionary; the Blue vocabulary picker renders only under `en`.
This is settled: florps and other cool ways to say tweet are an English-only feature.

- [[ui-i18n-6-plurals-and-dates]] — ICU plurals, `Intl` for dates and numbers, rewrite
  `human-time.pipe.ts` (which today hardcodes English "minutes ago" / "yesterday").
- [[ui-i18n-7-languages]] — translate the day-one eight: fr de ja fi is ru sv es.

Day-one locales are chosen to stress the machinery on purpose: **Russian** (6 plural categories),
**Finnish** (15 cases, long compounds that break narrow buttons), **Icelandic** (small corpus,
worst machine-translation quality), **Japanese** (no spaces, no plurals, different line-breaking).
If the pipeline survives those four it will survive the next fifty.
